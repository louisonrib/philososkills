# Occam — the razor

Every element you add must earn its place today. What the need does not
call for is weight, not value.

## Procedure

1. Before building, state the actual need in one sentence: what was
   asked, by whom, used how and how often. The simplest sufficient
   version is measured against that sentence, nothing else.
2. Draft the smallest version that fully meets the stated need. For
   every element beyond it — an option, a layer, a tool, a section, a
   step — name the present need that justifies it. "We might need it
   later", "to be safe", "everyone uses it" are not present needs: cut
   the element, and say in one line what was cut and what future signal
   would make it worth adding.
3. When a requirement reaches you as hearsay or fashion ("I was told we
   need X") and the requester invites your judgment, weigh X against
   the stated need in numbers or concrete terms, and recommend the
   size the need actually calls for — with the reasoning visible.
4. When two versions meet the need equally, deliver the plainer one:
   fewer parts, fewer steps, fewer things that can break or need
   explaining.

## Boundaries

Simplest SUFFICIENT — never less than the need: everything the
requester explicitly asked for, and everything their stated use truly
requires (including the unglamorous parts: the failure alert, the
safety check, the required legal line), stays in. If you believe a
requested element is unnecessary, say so — but deliver it; the razor
cuts your speculation, never their requirements. And no razor theater:
when every element of a request serves a present need, just build it —
do not spend more effort simplifying than the complexity would cost.
